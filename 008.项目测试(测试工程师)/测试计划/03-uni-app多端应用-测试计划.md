# uni-app 多端应用测试计划

> 对象：`007多端应用app开发/uni-app-应用`。本文件是测试设计，尚未运行设备测试；编译成功不能代替真机验收。

## 1. 技术栈、结构与启动

- 技术栈：uni-app Vue 3、Vite 5、DCloud `uni-app-plus`/`uni-mp-weixin`/`uni-h5`；目标为 Android、iOS、微信小程序，另有 H5 构建供辅助检查。
- `pages.json` 只注册一个 `pages/index/index` 页面，着陆、认证、流水、统计、预算、我的与账号安全由 `pages/index/index.vue` 内部状态切换；`pages/index/page.css` 管跨端布局；`components/Landing.vue` 为着陆页；`services/ledger.js` 封装远程 API 和本机游客数据；`config/api.js` 选择接口地址；`manifest.json` 配置应用和微信小程序；`static/` 放资源。
- 开发调试：HBuilderX 打开该目录后运行到 Android/iOS 设备或微信开发者工具；本机账号服务须已启动。当前开发默认接口为 `http://192.168.1.4:3000/api/v1`，设备需能访问该地址。命令行可执行 `npm run build:mp-weixin`、`npm run build:app`、`npm run build:h5`，但当前项目源文件在根目录，命令行构建时需将 `UNI_INPUT_DIR` 指向项目目录。
- 正式构建只在设置 `VITE_API_BASE_URL` 后有账号服务地址；未配置时登录/注册页面可见，但提交无法完成，本地体验仍可用。小程序发布环境还需实际可访问的 HTTPS 接口和相应合法域名配置。不要把调试时的局域网通路当成正式包可用性。

## 2. 核心业务与高风险点

| 模块 | 主要流程 | 风险等级与原因 |
| --- | --- | --- |
| 多端登录/游客 | 登录注册、退出、本地模式、Token 与接口地址 | P0：开发包和正式 APK/小程序配置不同，可能出现“调试能登录、安装包不能登录” |
| 账单与分类 | 弹窗记账、收支、日期、类别编辑删除、账单编辑删除 | P0：本地/云端路径不一致，保存失败或重复写入 |
| 本地合并云端 | 登录后手动合并游客账单 | P0：重复合并、类别映射错误、跨账号数据混入 |
| 预算与统计 | 月度总预算、分类预算、图表筛选和剩余计算 | P0：三个平台显示或计算不同，影响财务数据可信度 |
| 头像与账号 | 图片选取/压缩、资料编辑、改密、注销 | P1：各平台文件 API 不同；大图、权限和会话处理易失败 |
| 导航、搜索与布局 | 单页状态切换、搜索定位、弹窗、安全区/键盘 | P1：页面状态遗留、刘海屏遮挡、键盘盖住按钮、字符乱码 |

本项目未提供 Excel 导出，按需求不列为多端应用缺陷；Excel 导出应在网页版与后端计划中测试。`services/ledger.js` 的本机数据与后端数据是两套路径，必须分别验收。

## 3. 分层测试方案

1. **构建/静态层（每次变更）**：分别构建 Android/iOS 所用 App 包、微信小程序和 H5；检查模板编译、平台条件代码、资源路径与控制台错误。构建只验证可编译。
2. **服务逻辑层**：在本机模式验证账单、类别、预算、汇总、日期和搜索的输入边界；在账号模式验证请求字段、错误处理、Token 续期与本机合并幂等。
3. **页面交互层**：着陆→游客/登录→主导航→记账弹窗→预算弹窗→统计筛选→个人资料；打开、取消、保存、返回以及键盘弹出/收起均需覆盖。
4. **真机平台层**：Android 真机、iOS 真机和微信开发者工具加微信真机预览分别执行同一套 P0 用例，记录设备型号、系统版本、屏幕形态、构建类型及接口地址。H5 只作辅助，不代替 iOS/Android 验收。
5. **跨端集成层**：同一测试账号在 Android、iOS、小程序及网页版先后登录；A 端新增/编辑/删除账单与分类，B 端重新进入后核对数据；断网、重连、退出与重新登录后的数据一致性。
6. **发布包层**：对正式 APK、iOS 安装包和小程序体验版分别测试，不借用 HBuilderX 运行时状态；核对服务地址、合法域名、证书/网络限制及真实账号登录。

## 4. 首轮用例清单与测试矩阵

每个平台都执行：

- 认证：游客使用全功能；注册、登录、退出、重登；无接口地址、服务停止、断网、错误密码的提示；正式包是否具备正确接口地址。
- 账单：支出/收入各新增、编辑、删除；分类新增、重命名、删除后跨页面同步；金额、日期、长备注、重复点击保存、跨月数据。
- 预算统计：修改总预算与分类预算，核对剩余可分配、已支出、超支状态；类别筛选后图表和数字一起变化；空月/多类别/大量账单。
- 搜索与资料：关键词定位记录或页面；上传横图、竖图、大图并自动压缩，头像在个人页显示；修改昵称、简介、密码；注销流程只在隔离账号上测试。
- 设备表现：刘海屏/灵动岛、安卓不同状态栏高度、横竖屏、软键盘、底部手势区、系统字体放大；弹窗按钮可见、可点，无黑屏或可见乱码。
- 同步：同一账号三端交替修改并刷新；游客数据登录前不应自动上传，手动合并后每笔只出现一次；另一个账号不能看到前账号数据。

建议矩阵：Android 真机 × 开发包/正式 APK；iPhone 真机 × 调试包/正式安装包；微信开发者工具 × 小程序真机预览/体验版。每格至少跑 P0 冒烟，完整回归优先在三种真实运行环境各完成一次。若暂缺 iOS 设备或正式 HTTPS 服务，明确标为“未验证”，不能用 Android 或模拟器结果代替。

## 5. 数据准备、执行顺序与完成标准

准备两个隔离测试账号、游客空数据和含账单的游客数据；准备空月、普通月、超支月及多分类账本。保留接口地址和构建环境记录，测试前备份本机游客数据；不使用真实用户数据做注销或清除测试。

先确认三端构建与运行入口，再执行每端 P0 冒烟，随后做跨端同步、异常网络与布局回归，最后验证正式包。所有故障记录设备、版本、操作步骤、接口响应、截图和预期/实际结果。

完成标准：三端 P0 主流程和数据一致性通过；游客可独立完整记账；账号登录与云端同步在可用正式服务环境中通过；没有未解决的黑屏、数据丢失、越权或关键按钮不可点问题。尚无正式 HTTPS 服务时，正式包账号同步不能判定通过，应保持明确的待测项。
