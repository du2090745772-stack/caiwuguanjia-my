| 项目 | 内容 |
| --- | --- |
| 文档状态 | 需求梳理稿，供产品、设计、研发和测试评审 |
| 编写日期 | 2026-11-21 |
| 适用范围 | 现有 `004前端开发/画面设计` 用户端及其配套账号服务 |
| 目标 | 让授权管理人员查看注册用户、收入、支出、账单及系统运行情况 |
| 硬性约束 | **最多新建 1 张仅供后台使用的 `admin_accounts` 表；现有表、视图及其字段、索引、约束均不修改。后台对用户业务数据只读，不提供修改或删除用户数据的操作。** |

## 1. 产品定位与边界

后台是独立于用户端的管理界面，面向项目负责人及被授权的运营人员。它用于了解系统整体使用情况、核对用户账单与排查问题，不进入用户的记账流程。

- **统计对象**：已注册且数据已保存至现有 MySQL 的账号。免登录用户的数据仅在其浏览器中，后台无法汇总；首页必须明确注明这一口径。
- **数据边界**：除新建并维护唯一的后台专用 `admin_accounts` 表外，只读取现有业务表和视图；不改动其他表结构，不写入、修复或删除用户业务数据，也不后台代用户记账。
- **权限边界**：普通用户的 Token 只能访问本人数据。后台必须使用独立的管理员认证和服务端授权，不得仅靠隐藏页面或前端判断。
- **页面边界**：沿用用户端的品牌色、字体及卡片风格，但后台使用适合数据筛选、表格和图表的独立导航。
- **版本边界**：本文列出首版必做功能及后续候选功能；除后台专用表外，任何功能不得以新增其他表或修改现有表结构为前提。

## 2. 使用角色与权限

| 角色 | 可访问内容 | 说明 |
| --- | --- | --- |
| 管理员 | 全局概览、用户列表与详情、账单与收支统计、预算与分类统计、系统状态、导出 | 身份保存在后台专用 `admin_accounts` 表，由服务端校验；不得使用普通用户注册入口创建管理员。 |
| 运营查看者（后续） | 脱敏的汇总指标与趋势 | 不查看单个用户的账单、备注、头像、会话 IP 等资料。若无法独立可靠授权，首版先不开放此角色。 |

首版只有管理员可登录。登录后超时或退出须失效；访问任何管理接口均须重新验证权限。用户端 `/api/v1/data/*` 当前只按本人 `user_id` 读取，**不能直接复用为跨用户管理接口**。需要新增后台专用表、独立的只读业务查询接口及授权中间件；现有业务表保持原样。

### 2.1 唯一允许新增的后台专用表

`admin_accounts` 已在本机开发数据库 `daily_ledger` 中创建，仅用于后台管理员账号及其登录安全状态，不与普通用户账号混用。建表脚本见 `005数据库脚本/03_admin_accounts.sql`；当前未创建管理员账号。

| 字段 | 用途 |
| --- | --- |
| `id` | 管理员账号唯一标识 |
| `username` | 管理员登录名，唯一 |
| `password_hash`、`password_algo` | 仅保存加盐密码摘要和算法标识，不保存明文密码 |
| `role` | 权限角色；首版仅启用 `admin`，预留后续只读运营角色 |
| `status` | 启用或停用；停用后立即拒绝管理接口访问 |
| `failed_attempts`、`locked_until` | 管理员登录失败计数与临时锁定状态 |
| `last_login_at`、`created_at`、`updated_at` | 最近登录、创建和更新时间 |

- 初始管理员通过受控的服务端初始化流程创建；前台不提供公开注册入口，也不把密码写入配置文件或前端代码。
- 后台登录失败计数、登录时间、账号状态等更新仅写入 `admin_accounts`；普通用户的 `users`、`auth_sessions`、`bill_records` 等现有表不因后台访问而被改写。
- 管理员会话优先使用服务端短期会话及安全 Cookie；退出时使服务端会话失效。若部署为多实例，使用现有外部会话存储能力或在上线前补齐方案，**不得为会话再建第二张数据库表**。
- 管理操作审计记录进入受控应用日志或现有日志平台；**不得新增审计表**。若未来需要数据库内持久化审计，须另行评审并改变本约束，不能暗中增加表。

## 4. 页面及具体需求

### 4.1 管理员登录与导航（ADM-01，P0）

- 后台使用独立地址，例如 `/admin/`，与用户端页面分开；未登录访问管理页面直接进入管理员登录页。
- 登录失败给出明确提示，不向前端暴露管理员密钥、数据库连接信息或详细认证失败原因。
- 左侧导航：数据概览、用户、账单、收支分析、预算与分类、账号与系统、导出。顶部显示当前管理员身份与退出入口。
- 页面加载与接口请求均校验管理员身份；普通用户登录态访问管理接口应得到 `403`，未认证得到 `401`。
- 首版管理员凭据存入后台专用 `admin_accounts` 表；由受控的服务端初始化流程创建。**不得在前端硬编码密码，也不得在普通用户表添加 `is_admin` 字段**。

### 4.2 数据概览（ADM-02，P0）

默认展示最近 30 天，可切换今天、近 7 天、近 30 天和自定义日期范围。

| 指标 | 口径 | 展示 |
| --- | --- | --- |
| 注册用户总数 | `users` 当前账号数，注销冷静期账号单独列示 | 总量与区间新增 |
| 新增用户数 | `users.created_at` 落在所选时间范围内 | 数字与按日趋势 |
| 记账用户数 | 区间内有新增账单的去重 `user_id`；按 `bill_records.created_at` 判断实际操作时间 | 数字与趋势；不要与登录用户数混用 |
| 有效账单笔数 | `bill_records.deleted_at IS NULL`，按记账日期 `record_date` 落在范围内 | 总量、收入笔数、支出笔数 |
| 总收入／总支出／结余 | 有效账单金额分别求和；结余 = 总收入 − 总支出 | 金额卡片和收支对比图 |
| 人均记账笔数 | 区间有效账单笔数 ÷ 区间记账用户数，分母为 0 显示 `—` | 辅助指标 |

页面标明统计区间、最后更新时间和“仅统计已注册云端账号”。金额由数据库的“分”转换为“元”，统一保留两位小数。空数据展示空态，不显示原型示例数值。

### 4.3 用户列表与详情（ADM-03，P0）

- 列表支持按用户名、用户 ID 搜索；按注册时间、最近登录时间和账号状态筛选；分页并显示总数。
- 每行展示：用户 ID、用户名、网名、注册时间、最近登录时间、状态、账单笔数、累计收入、累计支出。头像仅在详情中按需加载。
- 用户详情包括：基础资料、账号状态、首次/最近记账时间、账单总量、累计收支、最近 12 个月收支趋势、最近账单、预算概况。
- 注销中的账号显示“冷静期中”及申请/预计到期时间；已完成清除且不再存在于 `users` 的账号，不应再被显示为正常用户。
- 密码摘要、Refresh Token 摘要和设备标识不展示、不导出。用户名和网名允许展示；备注属于用户私密内容，仅管理员点开单条账单详情后查看。
- 首版不提供“编辑用户”“重置密码”“代用户注销”按钮。

### 4.4 账单查询（ADM-04，P0）

- 查询条件：日期范围、收入/支出、用户名或用户 ID、分类名称、金额区间、备注关键词；条件可组合并可一键清空。
- 表格字段：记账日期、用户名、收支类型、分类、金额、备注摘要、创建时间；按记账日期倒序，支持翻页。
- 点击单条账单打开详情抽屉，显示完整备注、分类及创建时间。已删除账单默认不进入列表；如需排查删除记录，应有明确的“仅看已删除”筛选且只读。
- 顶部同步展示当前筛选结果的笔数、收入、支出和结余；计算范围必须与列表筛选一致。
- 后台不提供新增、修改、删除账单操作。

### 4.5 收支分析（ADM-05，P0）

- 折线或柱状图：按天/月统计收入、支出和结余；可切换区间，鼠标悬停或点按显示具体金额。
- 分类占比：分别查看支出分类与收入分类；点击分类查看对应账单。已删除但仍被历史账单引用的分类，保留在历史统计中并标注“已删除”。
- 排行：支出金额最高的分类、记账笔数最多的分类；可按所选时间范围变化。
- 用户分布：按累计支出区间或月记账频次分组，只显示聚合人数，不在图表上暴露单个用户身份。
- 图表、列表和导出使用同一筛选口径；无数据时显示“暂无数据”。

### 4.6 预算与分类（ADM-06，P1）

- 预算概览：所选月份设置过总预算的用户数、覆盖率、预算总额、已支出总额、达到 80%/100% 的用户数。
- 用户预算明细：按用户查询总预算、各分类预算、已用金额、使用率和剩余额度；只读。
- 分类分析：支出与收入分类分别统计分类数量、使用人数、账单笔数、金额排行；区分系统预置和用户自定义分类。
- 分类删除口径：查询有效分类时排除 `categories.deleted_at IS NOT NULL` 和隐藏分类；历史账单统计仍可依已有关联保留历史分类名称。
- 资金账户统计暂不作为首版验收项：现有表有 `wallet_accounts`，但要先确认用户端实际写入和关联账单的覆盖情况；无数据时不做模拟金额。

### 4.7 账号与系统状态（ADM-07，P1）

- 注销概览：冷静期中、已撤销、已清除的申请数量及时间趋势；只读查看 `account_deletions`。已清除账号只展示脱敏审计信息。
- 登录异常：按时间查看失败登录次数和锁定账号数量，仅显示聚合结果；IP 与设备信息默认不展示。
- 同步/迁移：按现有 `data_migrations` 查看成功、部分成功、失败数量及失败原因；如果该表尚无业务写入，显示“暂无同步任务数据”。
- 服务健康状态：独立显示后台 API 与数据库可用性、最近检查时间；不可把 `/healthz` 的成功等同于数据完整性。
- 本页不提供解除锁定、撤销注销或改写迁移状态等操作。

### 4.8 数据导出（ADM-08，P1）

- 支持导出用户列表、账单查询结果、收支汇总；导出范围必须与当前筛选一致。
- 格式为标准 `.xlsx`；文件名包含模块与日期范围。金额列保留数值类型，日期列可排序，中文用 Excel 打开无乱码。
- 导出前显示行数与筛选范围；单次导出设置合理上限，超限提示缩小时间范围。
- 默认不导出头像、完整备注、IP、设备信息或认证数据。若业务确需完整备注导出，应作为单独权限与显式操作设计，首版不开放。

## 5. 数据来源及当前可行性

| 数据/功能 | 现有来源 | 可行性与注意点 |
| --- | --- | --- |
| 用户基础信息 | `users`、`user_avatars` | 可查询；头像按需加载。`password_hash`、`password_algo` 不得出现在管理响应中。 |
| 用户收入、支出、账单 | `bill_records`、现有 `v_bill_monthly_summary` | 可按日期、用户聚合；金额源字段为分，且需排除账单删除标记。 |
| 分类 | `categories`、`category_templates` | 可区分收入/支出、预置/自定义、有效/已删除。 |
| 总预算、分类预算 | `budgets`、`budget_categories` | 可查询；预算周期按自然月 `YYYY-MM`。 |
| 登录与注销状态 | `auth_sessions`、`auth_login_attempts`、`account_deletions` | 可做只读状态与聚合；敏感字段不得回传前端。 |
| 同步与事件 | `data_migrations`、`analytics_events` | 表结构存在不代表事件已上报；上线前验证实际写入，缺数据时展示缺口。 |
| 管理员身份与跨用户接口 | `admin_accounts` 表已创建，管理接口尚未开发 | 仅使用此表存储管理员账号；仍需新增服务端管理员认证/授权和只读管理 API。现有业务表不改。 |

当前 `/api/v1/data/*` 使用普通用户的登录态，只能按本人 `user_id` 查询。管理后台不可从浏览器直连 MySQL，也不可通过普通用户接口循环读取其他账号。建议后端以独立路由提供分页、筛选与聚合结果；业务查询连接只授予现有业务表的读取权限，后台认证连接仅对 `admin_accounts` 授予必要的读写权限。除此表外，不修改数据库数据或结构。

## 6. 统一统计规则

1. **日期与时区**：页面采用北京时间展示；注册、登录、创建时间按存储时间转换。账单按用户选择的 `record_date` 归属统计日，用户活跃按实际 `created_at` 计算。
2. **金额**：数据库以分存储；服务端先以整数分聚合，再转换为元，避免前端浮点累加误差。
3. **删除与注销**：账单统计排除 `bill_records.deleted_at IS NOT NULL`；有效分类排除已删除或隐藏项；注销冷静期账号与正常账号分别展示。
4. **空值**：无最近登录时间、无预算、无同步记录分别显示“从未登录”“未设置”“暂无记录”；不得填充示例值。
5. **分页**：先在服务端完成筛选和聚合，再返回当前页及总数；不得把所有用户和账单一次性下载到浏览器后筛选。
6. **数据刷新**：列表和统计提供手动刷新；概览展示最近更新时间。首版不要求 WebSocket 实时推送。

## 7. 安全与隐私要求

- 所有管理 API 强制服务端鉴权，管理员访问与普通用户访问分离；生产环境使用 HTTPS，限制跨域来源。
- 业务数据访问使用只读权限；仅后台认证流程对 `admin_accounts` 有必要的读写权限。所有查询参数化，并限制日期跨度、分页大小和导出行数。
- 管理页面不展示密码摘要、Token 摘要、完整 IP、设备 ID；普通运营角色不接触用户级财务明细。
- 管理操作记录至少留在现有应用日志或受控日志平台中；单表约束下不规划新审计表。日志不得包含账单备注和认证秘密。
- 后台页面设置 `noindex, nofollow`，并禁止被搜索引擎或公开链接索引；前端隐藏入口不算权限控制。
- 账号注销到期后的数据清除遵循现有用户端规则，后台不得提供绕过冷静期的删除操作。

## 8. 验收标准

| 编号 | 验收场景 | 预期结果 |
| --- | --- | --- |
| A-01 | 普通用户 Token 或未登录请求管理 API | 分别返回 `403` 或 `401`，不返回任何其他用户数据。 |
| A-02 | 概览选择某月份 | 用户数、账单数、收入、支出与数据库按同一口径核对一致。 |
| A-03 | 以用户名、日期、类型组合筛选账单 | 列表、顶部汇总及导出范围一致。 |
| A-04 | 查看无账单、无预算、无事件的账号 | 显示真实空态，无原型示例数字。 |
| A-05 | 查询注销中及已删除分类 | 状态区分正确；历史账单仍可阅读，删除分类不进入有效分类列表。 |
| A-06 | 导出含中文备注和分类的 `.xlsx` | Excel 可直接打开，无乱码；金额可作为数值计算。 |
| A-07 | 检查管理响应和前端存储 | 不包含密码摘要、Refresh Token 摘要、数据库凭据等秘密。 |
| A-08 | 检查数据库变更 | 最多新增 `admin_accounts` 一张表；现有表和视图无字段、索引或约束变更，管理查询不修改用户业务数据。 |
| A-09 | 检查管理员认证数据 | 管理员账号及登录安全状态仅写入 `admin_accounts`；普通用户表无管理员字段，后台没有第二张专用表。 |

## 9. 建议实施顺序

1. **第一阶段（P0）**：管理员认证与只读 API、概览、用户列表/详情、账单查询、基本收支图表。
2. **第二阶段（P1）**：预算与分类、注销和系统状态、标准 Excel 导出、隐私与性能验收。
3. **第三阶段（P2）**：在真实埋点可用后补留存、渠道、功能漏斗；如需运营角色，先完成独立授权设计。
