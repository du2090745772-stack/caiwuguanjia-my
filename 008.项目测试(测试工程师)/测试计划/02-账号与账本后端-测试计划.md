# 账号与账本后端测试计划

> 对象：`004前端开发/框架开发`。本文件是测试设计，尚未运行测试或修改数据库。

## 1. 技术栈、结构与启动

- 技术栈：Node.js（`package.json` 要求 ≥22.12）、ES Modules、Express 5、MySQL 8 连接池（`mysql2`）、Argon2id、JWT、ExcelJS；现有 `node:test` 集成测试。
- `src/server.js` 启动服务并执行数据库连通检查及到期注销清理；`src/app.js` 挂静态页面、`/healthz`、`/api/v1/auth` 和 `/api/v1/data`；`src/auth/` 处理注册、登录、Token、会话和限流；`src/data/routes.js` 处理分类、账单、预算、汇总、资料、注销与导出；`src/http/` 处理 CORS 和错误；`src/middleware/` 校验登录态；`src/db.js` 为数据库访问；`test/auth.e2e.test.js` 是当前集成测试。
- 启动：按 `.env.example` 准备本机 `.env` 和 MySQL 库，`npm install` 后 `npm start`；开发监听可用 `npm run dev`；当前测试命令为 `npm test`。默认端口 3000，健康检查 `/healthz`。`双击启动.command` 同时打开网页版登录页。
- 现有集成测试会建用户、账单等测试数据并在结束时清理。因此正式执行前必须指向**隔离的测试数据库**，核对配置后再运行；本阶段不执行。

## 2. 核心业务与高风险点

| 模块 | 主要接口/职责 | 风险等级与原因 |
| --- | --- | --- |
| 认证与会话 | 注册、登录、Refresh、退出；密码哈希与 Token 吊销 | P0：账号接管、会话重放、错误续期 |
| 访问控制 | Bearer 校验、用户资源隔离、CORS、限流 | P0：跨账号读取/修改账单或绕过频控 |
| 分类与账单 | 分类增改删、账单增改删、历史分类显示 | P0：金额错误、重复导入、误删历史账单 |
| 月度预算与汇总 | 总预算/分类预算、月度收支、日趋势和分类汇总 | P0：跨月混算或分单位换算错误 |
| 资料与注销 | 个人资料、头像、改密、7 天注销期和清理 | P0：误清理、旧会话未失效、头像写入异常 |
| 数据导出 | JSON 账单导出、Excel 文件 | P1：数据缺漏、中文乱码、跨账号泄漏 |
| 启动与配置 | 环境变量、数据库连接、静态托管 | P1：服务假启动、测试误连生产库 |

代码检查发现服务在启动阶段会执行 `CREATE TABLE IF NOT EXISTS user_avatars`，并运行到期注销清理；这是测试环境隔离的额外原因。测试计划不授权修改现有数据库结构。

## 3. 分层测试方案

1. **纯逻辑/单元层**：用户名、密码、日期、金额转分、Token 时间与错误映射的有效/无效边界；限流计数与重试时间。可用无数据库的函数测试优先执行。
2. **HTTP 合同层**：逐个验证路径、状态码、错误结构、认证头、字段限制、Content-Type、CORS 预检、分页或月份参数。对未授权、错误用户和非法输入都检查没有数据写入。
3. **数据库集成层**：在隔离库中检验事务、外键、唯一索引、软删除、并发注册/重复账单 ID、预算覆盖和月份查询。读写前后用数据库记录核对接口返回。
4. **安全层**：跨账号越权、Token 伪造/过期/重放、登录失败限流、刷新轮换、改密后其他会话失效、注销期访问限制、异常消息不泄露密码或内部 SQL。
5. **端到端契约层**：与网页版和 uni-app 使用同一套测试账号走完整“注册→分类→记账→预算→统计→导出→退出/重新登录”路径，确认各端看到同一账本。
6. **运行层**：数据库不可用、服务重启、网络中断、配置缺失、并发请求和大头像/大量账单的响应与恢复；在允许的测试环境测关键接口延迟。

## 4. 首轮用例清单与现有覆盖

- 认证：注册成功、大小写重名、隐私未同意、弱密码；正确/错误登录不可枚举；账号/IP/设备限流；并发同名注册；Refresh 轮换和重放吊销；多个会话单独退出。这些主题已有 `test/auth.e2e.test.js` 用例，执行时仍需确认其结果和清理效果。
- 数据隔离：A、B 两账号相同月份分别记账；A 不能读取、修改或删除 B 的分类、账单、预算、资料；无 Token/伪造 Token 均拒绝。
- 金额与月份：0、负数、两位以上小数、超大数、月底/跨年/闰日；增删改账单后 `/summary`、`/analytics`、分类金额与 `/records` 一致；删除分类后历史账单仍可读。
- 幂等与并发：同一客户端账单 ID 重试不产生两笔；不同账号碰撞不能覆盖；并发预算修改和重复删除保持可解释结果。
- 安全资料：头像格式和大小边界、改密后旧密码与其他 Token 失效、注销前导出确认、7 天内恢复及到期清理；到期清理仅在隔离库验证。
- 导出：Excel 可打开，中文、金额、月份、分类与数据库一致；JSON 导出只含本人未删除记录；空月导出正常。
- 异常：MySQL 停止后 `/healthz` 与业务请求正确失败；请求体过大、非 JSON、未知路由、CORS 来源异常；日志不出现密码、密钥或完整 Token。

## 5. 环境、执行顺序与完成标准

测试库单独建库并配置独立 `.env`，准备两名普通用户及可控时钟/测试数据；禁止用真实用户账号做破坏性验证。先检查测试库地址，再执行已有 `npm test`，补齐失败或缺失的测试设计，最后做双端契约和性能测试。每次执行保留测试报告与数据库清理结果。

完成标准：所有 P0 认证、越权、金额与数据一致性用例通过；没有高危安全问题或未解释的数据丢失；核心 API 合同稳定；Excel 与跨端数据核对通过。仅有“测试文件存在”或 `/healthz` 返回成功不等于后端验收完成。
