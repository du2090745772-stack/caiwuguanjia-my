# 每日记账本 · Web（V1.0.1 实现）

按 `../001产品PRD（产品经理）/每日记账本-产品需求文档PRD-V1.0.1.md` 实现的响应式网页记账应用（V1.0 的记账/统计/预算/关怀模式 + V1.0.1 的 PG-09 注册登录页与 PG-11 账号管理）。
纯静态站点，无构建步骤、无第三方依赖。

## 运行

```bash
cd 002网站开发（研发）
python3 serve.py 8765      # 本地预览，已禁用缓存
# 打开 http://127.0.0.1:8765/          着陆页
#      http://127.0.0.1:8765/app.html  应用（默认 #/flow）
```

也可以直接双击 `index.html` 用 `file://` 打开：此时 IndexedDB 不可用，数据层自动退回 localStorage，功能一致。

## 与 PRD 的偏差（有意为之）

1. **文字色与图形色分离**。PRD 6.2 的功能色（暖粉 `#FF6B8A`、奶绿 `#7BC8A4`）与粉色主按钮上的白字，实测对比度分别约 2.7:1、2.0:1、2.2:1，达不到同文档「正文与金额文字 ≥4.5:1」的红线。实现保留这些色值用于图形、进度条与点缀，文字改用同色系的深色 `--expense-ink #C8305A`、`--income-ink #2F7D5B`，粉色按钮改用深墨字 `--on-brand`。
2. **关怀模式仍保留「设置」入口**。PRD CARE-01 要求底部导航只剩 3 项，若同时移除「我的」，用户开启后将无法关闭。因此在流水页顶部保留了设置图标。
3. **连续记账默认关闭**。PRD 主流程描述保存后回到列表，故默认保存即关闭面板，「我的」中可开启。
4. **不使用图表库**。统计图用手写 SVG 实现，以满足首屏 ≤500KB gzip 的性能要求（当前约 39KB gzip）。
5. **分类图标使用 Emoji**，PRD 6.4 期望软萌 SVG 插画，需设计侧提供素材后替换；`Store.DEFAULT_CATEGORIES` 与分类编辑器的图标库是集中定义，替换点明确。

- 浏览器实测（Chrome，127.0.0.1）：记账主流程、键盘快捷键路径、编辑与删除二次确认、弹层栈与 Esc 层级、搜索四类筛选、预算横幅与进度、分类增删改排序与隐藏、关怀模式规格（18px 正文 / 48px 热区 / 文案切换）、深色与跟随系统、CSV 导出（BOM + 22 行）、着陆页 CTA 状态切换，均无控制台报错。

## 已知限制

- 账号体系是**本机演示**：`js/auth.js` 把用户名、密码摘要与「备份快照」都写进 IndexedDB 的 `auth_state`，没有网络请求。文案统一说「在本机生成备份快照」，不宣称数据已上云；接真后端时只需替换 `js/auth.js`，接口形状对齐 `/api/v1/auth/register|login|refresh|session`。
- 演示层用 FNV-1a 双轮摘要避免本机留明文密码，**不构成密码学安全**；正式版的哈希与校验都在服务端（argon2id/bcrypt）。
- 没有邮箱与手机号，因此本版无自助找回密码：「忘记密码」只能说明情况并清除这台设备上的账号，找回链路排在 V1.1。
- 待备份计数只比对笔数与 `updated_at`，新增一笔同时删除一笔会相互抵消（单测已锁定该行为）。
- 合并规则通过单测，但没有真实云端可验证；多设备同步、异地登录提醒仍未实现。
- 埋点（EV-11/12/13）未接入，PRD 的转化率与成功率指标本版无法采集。
- 清理浏览器数据会丢账单，因此导出入口在「我的」与提示横幅中都保留。
- 下拉刷新只在移动端触摸环境生效，需真机或设备模拟验证；本次自动化环境无法渲染截图，视觉细节（字体圆角观感、图表配色观感）请人工过一遍。
- `localStorage` 兜底模式下容量约 5MB，达到配额时会在页面底部提示导出备份。
