# 每日记账本后台管理系统

本目录按用户端 `004前端开发` 的方式分为 `画面设计`（HTML、CSS、JavaScript）和 `框架开发`（Node.js、Express、MySQL）。后台默认在 `http://127.0.0.1:3100/` 独立运行。

## 启动

在 `框架开发` 目录执行：

```bash
npm ci
cp .env.example .env
```

编辑 `.env` 中的数据库连接值，并设置不少于 32 字符的 `ADMIN_SESSION_SECRET`。本机开发环境的 `.env` 已配置，无需重复复制。确认 MySQL 中已执行 `005数据库脚本/03_admin_accounts.sql`，然后运行：

```bash
npm run create-admin
npm start
```

`create-admin` 仅在终端交互输入密码，不回显，也不会写入配置文件。首次账号已在本机数据库创建，只有需要增加管理员时才运行此命令。浏览器打开 `http://127.0.0.1:3100/`，也可以双击目录中的 `启动后台.command`。直接双击 `画面设计/index.html` 时，若后台服务已启动会自动跳转到服务地址；若服务未启动则显示启动提示。开发时可用 `npm run dev`。运行 `npm test` 可验证鉴权、查询与 Excel 导出。

## 功能

- 概览：按日期看注册、记账、收支和趋势。
- 用户：搜索、分页、状态、资料与最近账单。
- 账单：跨用户组合筛选、详情、已删除记录查询。
- 分析：按日或月趋势、分类排行、用户记账频次。
- 预算与分类：月度预算覆盖、使用情况及分类统计。
- 系统：注销、登录异常、迁移与服务状态。
- 导出：当前筛选范围的用户、账单、收支汇总 `.xlsx`。

只统计已注册且已保存到 MySQL 的账号。后台业务接口只读，管理员身份与登录安全状态仅写入现有的 `admin_accounts` 表；没有修改其他业务表或表结构。页面不保存管理员密码、令牌或数据库凭据。

## 部署注意

生产环境须使用 HTTPS、独立的高强度会话密钥和最小权限数据库账号。管理员会话目前保存在单个 Node 进程内，重启后全部失效；多实例部署需要使用现有外部会话存储方案。单次导出最多 10,000 行，超出时缩小筛选范围。
