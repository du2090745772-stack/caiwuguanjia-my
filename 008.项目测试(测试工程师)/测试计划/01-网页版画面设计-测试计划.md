# 网页版画面设计测试计划

> 对象：`004前端开发/画面设计`。本文件是测试设计，尚未执行用例；下文的“预期”不代表已通过。

## 1. 技术栈、结构与启动

- 技术栈：多页静态 HTML、CSS、原生 JavaScript；页面引入 Tailwind CDN 和 Google Fonts。无本目录独立打包流程。游客数据使用浏览器 `localStorage`，登录数据经 `fetch` 调用同级后端 `/api/v1`。
- `index.html` 跳转 `pages/landing.html`；`pages/` 为着陆、登录、注册、流水、记账、统计、预算、个人主页等 15 张页面及空态；`assets/css/` 管样式；`assets/js/api.js` 管认证与 Token，`app.js` 管页面交互，`cloud-native.js` 管云端/游客数据展示，`modals.js` 管记账与预算弹窗，`site-search.js` 管搜索，`prototype-navigation.js` 管导航；`docs/` 存设计说明与截图。
- 首选启动：先配置并启动 `004前端开发/框架开发` 的 MySQL 与账号服务，再双击该目录的 `双击启动.command` 或执行 `npm start`，访问 `http://127.0.0.1:3000/pages/landing.html`。独立静态预览可在画面设计目录执行 `python3 -m http.server 8080`，但登录仍依赖后端和 CORS 配置。`file://` 不是完整功能测试入口。

## 2. 核心业务与高风险点

| 模块 | 主要流程 | 风险等级与原因 |
| --- | --- | --- |
| 登录/注册/退出 | 表单校验、会话保存、到期续期、游客切换 | P0：可能出现“页面像已登录但接口无权限”、退出后数据串用 |
| 记账与分类 | 收支切换、金额/日期/备注、分类新增编辑删除、弹窗保存 | P0：数据丢失、重复提交、分类删除后历史账单异常 |
| 游客与云端数据 | 本机账单、登录后保留旧账单、手动合并 | P0：误上传、重复合并、游客数据污染账号或被清空 |
| 预算与统计 | 月份、总预算/分类预算、剩余/超支、图表与分类筛选 | P0：汇总不一致会直接误导用户财务判断 |
| 个人资料与头像 | 编辑昵称、简介、头像与账号安全入口 | P1：上传失败、图像变形、跨页不刷新 |
| 搜索与导出 | 关键词结果跳转、Excel 导出 | P1：跳转错页、导出乱码或金额/月份错误 |
| 响应式布局 | 桌面、窄屏、触屏、弹窗和安全区 | P1：按钮遮挡、内容溢出或弹窗无法完成操作 |

重点关注代码中 `localStorage` 与远端数据两套路径的切换，以及 `app.js`、`cloud-native.js`、`modals.js` 对同一页面的共同处理。页面 HTML 带有演示内容，测试必须辨别真实接口数据与静态样例。

## 3. 分层测试方案

1. **静态检查（每次变更）**：检查页面链接、脚本引用、控制台错误、失效资源和可见乱码；核对关键按钮有真实动作。保留桌面与手机基准截图，比对主要布局，不用像素级一致代替功能判断。
2. **逻辑层**：验证金额和日期格式、月份切换、类别选择、预算剩余与图表筛选、搜索匹配与排序。优先覆盖空数据、零预算、超支、跨月、闰日、长文字。
3. **组件/页面层**：逐页走着陆→游客→记账→流水→统计→预算→我的，以及注册→登录→同样路径；弹窗打开、取消、保存、键盘/触屏操作均需覆盖。
4. **接口联调层**：用隔离测试账号验证前端展示与后端实际记录一致；登录过期、断网、接口 4xx/5xx、重复点击和刷新页面后状态恢复。
5. **端到端回归层**：Chrome、Safari 各测桌面与手机视口；至少一次真实触屏测试。验证账单、分类、预算的修改跨页同步，以及退出后游客仍可独立使用。

## 4. 首轮用例清单与数据

- 认证：注册成功/重名/非法用户名/弱密码；登录成功/失败；刷新浏览器仍登录；过期自动续期；退出后立即显示游客；游客点击登录可返回登录页。
- 账单：支出/收入各新增一笔，编辑金额与日期，删除并刷新；输入空值、负值、超长备注；日期选择年/月/日；类别双击编辑和单独删除；分类变化同步到预算、统计、账单。
- 预算统计：设置总预算与多个分类预算，检查“剩余可分配”；同月增删账单后预算支出、统计总额和分类占比同步；切到空月和超支月；分类筛选切换时图表与相关数字一致。
- 游客合并：游客造 2 笔记录后登录，未确认时云端不应增加；确认合并一次与重复执行结果一致；退出账号后本机游客记录仍可见，且不会显示另一账号资料。
- 搜索与文件：按页面名称、分类、备注、金额搜索并点击跳转；下载 Excel 后用 Excel/Numbers 打开，核对中文、日期、金额和合计。
- 图片与布局：大尺寸照片上传后自动处理，头像在个人页显示正常；窄屏无横向溢出，顶部和底部按钮可点击，记账/预算弹窗可在可视区域内完成。

准备至少两个测试账号、一个游客浏览器配置、一个空账本、一个含历史月与超支月的账本。测试账号只用于隔离环境；不清除用户现有浏览器数据或真实数据库记录。

## 5. 执行顺序与完成标准

先完成 P0 主流程与数据一致性，再做 P1 搜索、导出、头像和布局，最后做跨浏览器回归。记录每个失败的复现步骤、环境、截图/控制台信息、接口响应和实际/预期差异。

进入下一阶段的门槛：P0 用例全部通过且无未解决 P0/P1 数据损坏问题；游客与登录数据隔离、账单/预算/统计一致、主要导航可用；已知的设计样例与未实现页面单独列为限制，不算功能通过。
